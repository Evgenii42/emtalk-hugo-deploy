# Bret: картинка и видео в медитациях

Это дополнение к простому каталогу schemaVersion=1. Источник: `https://www.emtalk.org/content/bret/meditations/index.json`, затем `jsonUrl` выбранной записи. Все ссылки в JSON разрешаются относительно origin самого JSON. Старые `backgroundImageUrl` и `thumbnailUrl` сохраняются. Контракт добавляет только необязательный `backgroundVideo` в detail. Нативную поддержку можно реализовать позже; существующий клиент может игнорировать новое поле.

## Поля backgroundVideo

| Поле | Тип и смысл |
| --- | --- |
| `url` | Прямая ссылка `/media/bret/.../backgroundVideo-<hash>.webm` |
| `mimeType` | `video/webm` |
| `codecs` | `vp9`; проверять декодер, наличие расширения файла недостаточно |
| `posterImageUrl` | Соответствующий видео WebP кадр, пока видео загружается или не воспроизводится |
| `width`, `height` | Положительные целые, размер кодированного видео в пикселях |
| `durationMs` | Длительность одного видеоповтора, не длительность медитации |
| `bytes` | Полный размер WebM для бюджета загрузки/кеша |
| `sha256` | SHA256 точных байтов WebM, lowercase hex64 |

JSON Schema объекта публикуется на том же origin: `/bret/meditation/background-video.schema.json`. Полный актуальный пример получать по `jsonUrl`, не копировать сюда устаревающие версии/хеши. Поле отсутствует, если видео не предлагается; `null` издатель не отправляет. Неизвестные дополнительные поля игнорировать. Повреждение необязательного объекта видео у клиента означает отказ от анимации, а не отказ от всей медитации.

## Поведение клиента

1. Для каталога загружать только миниатюры. Не скачивать видео всех медитаций при получении index. Выбор категории работает по прежнему index `categoryId`.
2. При отключённой анимации, системном reduced motion или режиме экономии трафика/энергии показывать прежний `backgroundImageUrl`. При отсутствии возможности видео тоже использовать его, не запрашивая video/poster. Сначала поддержка картинки, затем необязательная поддержка видео. Возможность выключить движение остаётся доступной отдельно от управления аудио.
3. Если видео разрешено и кодек поддерживается, показать `backgroundVideo.posterImageUrl` и начать muted/inline/loop при открытии detail, ещё до Start аудио. Проверять `video/webm; codecs="vp9"` средствами платформы до загрузки. Файл содержит только видео, без звуковой дорожки. Autoplay не должен запускать звук медитации. Отказ autoplay сохраняет картинку и честный ручной запуск, без ложного статуса playing.
4. WebM повторяется независимо от аудио: сейчас один цикл 16с, аудио Clear focus 418600мс, Time to unwind 448000мс. Не сбрасывать audio position на видеостыке, не использовать видеовремя для субтитров, не останавливать медитацию при окончании/ошибке видео. Start/Resume аудио включает или возобновляет видео, если движение разрешено и пользователь отдельно его не выключил. Pause аудио ставит видео на паузу. Отдельная пауза движения не останавливает аудио и сохраняется до явного включения движения. По окончании аудио остановить видео и показать соответствующий poster; Replay начинает аудио и видеоповтор с нуля при разрешённом движении. При закрытии плеера/уходе в фон остановить видео. Сам возврат в foreground не запускает его снова; запуск через Start/Resume или отдельное включение движения. При наличии системной фоновой аудиосессии это правило видео не останавливает аудио само по себе.
5. Если кодек сразу не поддерживается, использовать прежний `backgroundImageUrl` без загрузки видео. После начала выбранной анимации при сетевой ошибке, отсутствии места/кеша или ошибке декодера оставить соответствующий poster; если он недоступен, использовать `backgroundImageUrl`, затем нейтральный фон. Аудио и controls должны продолжать работать. Не зацикливать повторные запросы; предлагать ручной retry. Отсутствие анимации не является ошибкой самой медитации.
6. Кешировать отдельно по полному URL/хешу. Видео необязательно для offline-ready аудиопрактики. Приоритет у JSON, Opus и обычного фона. Проверять `bytes` и `sha256` после полного скачивания перед добавлением файла в постоянный кеш, при нехватке места удалять необязательное видео по ограниченному LRU. Сохранять предыдущую согласованную копию JSON/медиа при обновлении. Не обещать сетевую перемотку без подтверждённого Range; полная загрузка допустима.
7. ID, категории, аудио, субтитры, durationMs верхнего уровня и правила Play/Pause/seek/окончания остаются прежними. Субтитры пока draft `needs_review`. Дополнительные регуляторы voice/music отсутствуют: Opus содержит готовый микс.

Смена любого текста, ссылки или video metadata меняет detail `version`, затем совпадающую `meditations[].version` в index и корневую `version`. Версии сравниваются только на равенство. Новая ссылка содержит новый content hash, старый файл не перезаписывается. Совместимое добавление optional поля не меняет schemaVersion. Старый кеш без категорий и без видео продолжает давать общий список и обычную картинку. При рассогласовании версий заново получить index/detail с revalidation не более двух раз, затем сохранить последнюю согласованную копию или показать retry.

## Минимальная заготовка Kotlin

Это пример будущего DTO, не уже реализованный мобильный плеер:

```kotlin
@Serializable
data class BackgroundVideoDto(
    val url: String,
    val mimeType: String,
    val codecs: String,
    val posterImageUrl: String,
    val width: Int,
    val height: Int,
    val durationMs: Long,
    val bytes: Long,
    val sha256: String,
)
// В detail DTO сохранять необязательное поле как JsonElement? = null.
// Это изолирует некорректный вложенный объект от разбора обязательных audio полей.
val candidate = detail.backgroundVideo?.let { raw ->
    runCatching { json.decodeFromJsonElement<BackgroundVideoDto>(raw) }.getOrNull()
}
// json = Json { ignoreUnknownKeys = true }
// Затем отдельно проверить URL/origin, bounds/hash и codec support.
// При любой неудаче использовать картинку; nullable DTO сам по себе этого не обеспечивает.
```

Проверенный локальный Android/KMP source `dd1570153e2a1c0f3b99339675b07bfd55378cb0`: HomeViewModel.kt по Meditation пока показывает NotImplementedYet, KtorClientFactory.kt включает ignoreUnknownKeys=true. Нового DTO/видеоплеера для медитаций в этом исходнике не найдено. Это подтверждает возможность будущего additive parsing, но не доказывает фактическую поддержку WebM/Opus, iOS или согласованность опубликованной мобильной сборки. Native запуск в этом инкременте не выполняется.

Фактические версии, файлы, полный media decode и CDN/readback evidence хранятся в `docs/bret-meditations/video-contract-2026-11-24`. Публикация считается подтверждённой только после заполненного deployment/readback отчёта, наличие этого документа её не доказывает.
